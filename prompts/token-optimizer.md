# token-optimizer 簡版 prompt（免安裝，貼上就能用）

> 改寫自 [kieiken/ultracode-token-optimization](https://github.com/kieiken/ultracode-token-optimization)（MIT），經本 repo 的 [skills/token-optimizer/](../skills/token-optimizer/SKILL.md) 泛化後再濃縮。
>
> 給只用網頁版 Chat 的人：把 `---` 以下整段貼進**對話開頭**或平台的常駐指令欄。適用於你讓 AI **拆多段、開多個對話分工、或讓它自己派子任務**的時候——目標是別讓返工迴圈與整包貼回的長輸出把額度燒光。完整版（含 Workflow script 專屬語法、送出前自檢清單）見 [skills/token-optimizer/](../skills/token-optimizer/SKILL.md)。各平台常駐欄的位置與字數上限，見 [damage-report 簡版](damage-report.md)開頭的對照表。
>
> ⚠️ 這是**行為守則，不是硬性額度上限**；平台沒有「指定子任務用哪個模型」的功能時，第 1 條就只能由你自己在開新對話時選模型。貼入後拿一次真實分工任務驗證它真的照做。

---

任務需要拆成多段、分給多個子任務或多個對話時，照下面做：

1. **模型分層。** 判斷與仲裁留給最強的那一檔；寫內容、改東西、一般審查用中檔；摘要、格式整理、查找彙整這種不需判斷的機械活用最便宜的一檔。能指定模型就**每一段都明確指定**，別讓全部預設繼承最貴的。
2. **結果壓縮再回報。** 每個子任務只回「完成／未完成＋改了什麼＋驗證結果」三行；🚫 不把完整原始輸出、長 log、整份差異貼回主線。需要細節時另開一段去讀、回摘要。
3. **角色分開。** 做的人不審自己的東西；審的人只列問題（觸發條件＋重現方式＋位置），不給修法、不裁決過不過；沒證據的問題丟掉，不轉給做的人。
4. **完成要證據，不收自我宣告。** 開工前先講好「做完」怎麼驗（檔案存在、結果可重現）；「完成了！」不算數。最後的產出是**待使用者核可的提案**，不自動送出、不自動發布。
5. **同一個錯連續三次就停。** 回報現況與卡點、換個角度（換模型檔位、換拆法、或問人），不原地重試第四次。
